Patches, attention and Vision Transformers

A convolutional network is built on an assumption: what matters is nearby. A Vision Transformer throws that assumption away. It chops the image into patches, treats them as a sequence, and lets every patch look at every other patch from the very first layer. Below is a real one — single head, written by hand, trained live on this page — with its attention maps exposed.

Step 1 · An image becomes a sequence

A transformer has no idea what an image is. It processes sequences of vectors, so the first job is to turn a picture into one: slice it into a grid of non-overlapping squares, flatten each square into a list of numbers, and multiply each by a learned matrix to get a token. A 20×20 image with 4×4 patches becomes 25 tokens.

Flattening destroys all spatial information — token 7 has no idea it came from the middle of the second row. So the model adds a learned position embedding to each token: a little vector that means "I am patch 7". Position in a transformer isn't structural, it's something the model has to be told, and then has to learn to use.

Patch size is the central trade in a ViT. Big patches mean few tokens and cheap attention, but each token is a coarse summary. Small patches see fine detail and cost far more — attention compares every token with every other, so halving the patch size roughly sixteen-times the attention work.

Step 2 · What attention computes

Each token produces three vectors by multiplying itself with three learned matrices:

Query

What am I looking for? Emitted by the token doing the looking.

Key

What do I contain? A label other tokens can match against.

Value

What do I pass on if someone attends to me?

Compare every query against every key with a dot product, scale, and softmax the result into weights that sum to one. Each token's output is the weighted average of everyone's values:

attention(Q, K, V)  =  softmax( Q·Kᵀ / √d ) · V

That's the entire mechanism. It's a soft, differentiable lookup: find the tokens whose keys match my query, and mix their values together. Nothing in it knows about images, neighbourhoods or edges — which is exactly why the same operation drives language models too.

Why √d?

Dot products of d-dimensional vectors grow with d. Without the scaling the scores get large, softmax saturates into a hard one-hot pick, and the gradient through it nearly vanishes. Dividing by √d keeps the scores in the range where softmax stays soft and trainable — a one-symbol fix for a real training failure.

Training

Configuration

Two real design choices, switchable. The class token is an extra learned token that attends to every patch and whose output feeds the classifier — the arrangement used by the ViT paper. The alternative simply averages the patch tokens. LayerNorm normalises each token before each block; without it a deeper stack becomes hard to train, though at this size you may find it costs more than it gives.

Step 4 · What the position embeddings learned

Each tile below belongs to one patch position, and shows how similar that position's learned embedding is to every other position's. Red is similar, blue is dissimilar.

At initialisation these are random static. As training proceeds, each tile typically develops a bright spot at its own location and a soft glow around it — the model has worked out, from nothing but the data, which patches are neighbours. It had to learn the grid layout that a convolution gets for free from its architecture. That's the core trade of the whole approach: fewer built-in assumptions, more that must be learned, and therefore a much bigger appetite for data.

CNN or transformer?

On this page the CNN wins, and it should: 1,000 tiny images is exactly the regime where built-in assumptions pay. A convolution starts life already knowing that pixels near each other belong together and that a pattern means the same thing wherever it appears. The transformer starts knowing nothing and must learn both facts from examples.

Flip the data budget and the ranking flips with it. Given hundreds of millions of images, the transformer's lack of assumptions becomes freedom: it can learn relationships a 3×3 kernel structurally cannot express — the top-left of an image directly informing the bottom-right in layer one. That is the actual finding of the ViT paper, and it is the reason both architectures are still in use.

What's missing here, honestly

A production ViT has multiple attention heads per layer (this has one), a dozen or more stacked blocks (this has one), layer normalisation before each block, dropout, and a dedicated classification token instead of averaging. Each is a fix for a real problem that appears at scale. What's on this page is the load-bearing idea with the scaffolding removed.

Experiments worth running

  • Look at the attention before training, then after. Untrained maps are flat — every patch attends to everything about equally. Trained maps concentrate. That change is the model deciding what's worth looking at.
  • Switch to "average attention received". After training, the bright patches usually sit on the digit's strokes rather than the empty background. Nobody labelled the strokes; attention found them because they carry the information.
  • Set patches to 10×10 (a 2×2 grid). Four tokens is nearly no spatial resolution and accuracy collapses. Then try 2×2 patches: 100 tokens, far more attention arithmetic, slower training — and not obviously better at this size.
  • Shrink the embedding to 8. Queries and keys now live in eight dimensions, so tokens can barely distinguish themselves and attention gets muddy.
  • Draw a digit far off centre. Compare how the CNN and the transformer cope. Neither is truly translation invariant at the output, but they fail differently.
  • Train, then set augmentation to 0 and regenerate. Watch the test accuracy jump — not because the model improved, but because the exam got easier. Always ask what a benchmark number is measuring.
