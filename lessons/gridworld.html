Reinforcement learning from zero

Before a neural network drives a car, get the idea underneath it from something small enough to see all at once. The agent here knows nothing about the maze you draw. It walks into walls, falls into pits, and gradually fills in a number for every move in every square, until a route appears that nobody ever told it about.

The setup: states, actions, rewards

Every reinforcement learning problem is built from the same four pieces. Worth naming them on something this small before any maths turns up:

State

Which square the agent is standing on. 88 of them here.

Action

Up, right, down or left. Four choices, every step.

Reward

+1 for the goal, −1 for a pit, and a small cost for every step taken.

Policy

The rule it follows: which action to pick in each state. This is what gets learned.

The agent's memory is one table, called Q. For every square and every direction it stores a single number answering: if I go this way from here and play sensibly afterwards, how much total reward should I expect? Each square below is drawn as four triangles, one per direction, shaded by that number. Green means promising, red means regret.

Progress

Steps per episode is the clearest sign that anything is happening. It starts in the hundreds, which is just wandering, and falls toward the length of the shortest safe route.

The one equation

Every step the agent takes runs this one update, and nothing else. This is the entire algorithm:

Q(s,a)  ←  Q(s,a)  +  α [ r + γ maxa′ Q(s′,a′) − Q(s,a) ]

Read it as a correction. The green part is a fresh estimate of what that move was worth: the reward you just collected, plus the discounted value of the best move available from wherever you ended up. The blue part is what you believed a moment ago. The gap between them is the surprise, and α decides how much of the surprise you're willing to believe.

The clever bit is that max. The agent bootstraps, improving one of its guesses using another of its guesses. Early on every guess is zero and nothing appears to happen, right up until the first accidental arrival at the goal. That single +1 then walks one square backwards per visit. Set the speed to "Step by step" straight after a success and you can watch the value crawl back down the corridor.

Race it yourself

Press Race the agent and walk the maze yourself, arrow keys or the on-screen pad. You'll almost certainly win. The interesting bit is why: you can see the entire grid at once and you already knew what a pit was before you started. The agent gets one square of feedback at a time and had to discover that pits are bad by falling into several. Every impressive RL result you've read about is a system solving its problem under that handicap.

Exploration versus exploitation

With ε = 0 the agent always takes whatever move it currently rates highest. That sounds sensible and is frequently fatal: the first mediocre route it stumbles on becomes the only route it will ever consider, because it never tries anything else for long enough to learn better. With ε = 1 it wanders forever and builds a lovely Q-table it never uses. Every RL algorithm ever written is some answer to that tension, including the entropy bonus over in the Rocket League lesson.

Hyperparameters

Experiments worth running

  • The cliff. Load "Cliff walk". The quick route runs along the lip of a row of pits and the safe route goes the long way round. Now push ε up to 0.4 and watch the agent start avoiding the edge. With random moves in the mix, walking next to a cliff genuinely is worse. It isn't being timid, it's being right about the world it lives in.
  • Turn off the step cost. Set it to 0.000. The agent still gets to the goal, it just stops caring how long that takes, and the arrows go from a clean route to an aimless drift. Charging for time is what makes a policy efficient.
  • Make the floor slippery. At 40% slip, actions only mostly work. Watch the values near pits go deeply negative as the agent learns to keep a safety margin, which is exactly the instinct you'd want in a robot.
  • Drop γ to 0.6. Distant rewards get discounted into irrelevance, and in a long maze the agent can no longer see far enough ahead to care.
  • Move the goal mid-run. Draw a new goal somewhere else while it's running. Every value in the table is now a lie, and unlearning takes real time. Environments that change underneath you are hard for exactly this reason.
Where this stops working

The Q-table keeps one row per state, which is fine for 88 squares. A Rocket League arena has continuous positions, velocities and angles, so there are infinitely many states and no two episodes ever visit the same one twice. The next lesson swaps the table for a neural network that can generalise to states it has never seen. That swap is the whole of deep reinforcement learning.
